## 2. Input Representation & Data Preprocessing Audit

### 2.1 File Location & Caching
- **Primary Processed File:** `data/processed/mmasd_openpose/mmasd_openpose_64frames.npz`
- **Data Loading Function:** `novel_contribution.data_processing.dataset_loader.load_raw_mmasd()`
- **Stored Keys:**
  - `X`: Shape `(1374, 64, 25, 4)`, `float32`
  - `Q`: Shape `(1374, 64, 25)`, `float32`
  - `y`: Shape `(1374,)`, `int64` (values 0–9)
  - `groups`: Shape `(1374,)`, `str` (32 unique cohort identifiers)
  - `clips`: Shape `(1374,)`, `str` (1,374 unique clip directory strings)
  - `classes`: Shape `(10,)`, `str` (`["as", "bs", "ce", "dr", "mfs", "ms", "sac", "sq", "tr", "tw"]`)

### 2.2 Input Tensor Dimensions Explained
- **Sequence Length ($T = 64$):** Skeletons are uniformly resampled or padded to 64 frames.
- **Joint Count ($V = 25$):** Standard OpenPose `BODY_25` skeleton model.
- **Feature Channels ($C = 4$):**
  - Channel 0: Normalized joint $x$-coordinate.
  - Channel 1: Normalized joint $y$-coordinate.
  - Channel 2: Normalized inter-frame horizontal velocity $v_x(t) = (x(t) - x(t-1)) / \Delta t$.
  - Channel 3: Normalized inter-frame vertical velocity $v_y(t) = (y(t) - y(t-1)) / \Delta t$.
- **Detection Confidence ($Q$ in $\mathbb{R}^{B \times T \times V}$):** Raw scalar detection scores $c_{v}(t) \in [0, 1]$ generated by the OpenPose CNN detector.

### 2.3 Normalization Protocol & Leakage Safeguards
In `novel_contribution.data_processing.dataset_loader.partition_train_val_test`:
- Mean ($\mu$) and standard deviation ($\sigma$) are calculated **strictly on the fit partition of the outer training fold**:
  $$\mu = \frac{1}{|D_{\text{fit}}| \cdot T \cdot V} \sum X_{\text{fit}}, \quad \sigma = \sqrt{\frac{1}{|D_{\text{fit}}| \cdot T \cdot V} \sum (X_{\text{fit}} - \mu)^2}$$
- Held-out validation and test partitions are normalized using the fit fold's $\mu$ and $\sigma$, followed by clipping to $[-8.0, 8.0]$.
- **Zero-leakage assertion verified:** Assert statements explicitly check that $\text{groups}(D_{\text{fit}}) \cap \text{groups}(D_{\text{val}}) = \emptyset$ and $\text{groups}(D_{\text{fit}}) \cap \text{groups}(D_{\text{test}}) = \emptyset$.

### 3.3 E2 Fixed Bilateral Topology Implementation
In `research_stage2/models/pr_gat.py`, E2 introduced the following fixed relational edges:
```python
RELATIONAL_EDGES = [
    (7, 4), (4, 7),   # LWrist <-> RWrist
    (14, 11), (11, 14), # LAnkle <-> RAnkle
    (7, 0), (0, 7),   # LWrist <-> Nose
    (4, 0), (0, 4)    # RWrist <-> Nose
]
```
These edges were permanently registered into a static boolean adjacency mask:
```python
mask = self.adj.view(1, 1, 1, v, v) <= 0.0
attn_logits = attn_logits.masked_fill(mask, -1e9)
```
**Limitation Identified for Stage 4:**  
The relational adjacency is binary and static ($A_{uv} \in \{0, 1\}$). The attention weights $\alpha_{uv}$ are modulated post-softmax by static reliability, but the model cannot dynamically adjust edge presence based on movement context or selective limb engagement.

## 4. Reliability Gating Mechanism Audit

### 4.1 Joint Kinematic Prior (`ReliabilityEstimator`)
Located in `novel_contribution/reliability_estimation/velocity_prior.py`:
- Joint velocity: $v_i(t) = \frac{\|\mathbf{x}_i(t) - \mathbf{x}_i(t-1)\|_2}{\Delta t}$
- Velocity dispersion $\sigma_{v,i}$ is computed per joint over the training partition.
- Kinematic velocity prior: $p_{\text{vel}}(v_i(t)) = \exp\left(-\frac{v_i(t)^2}{2\sigma_{v,i}^2}\right)$
- Calibrated joint reliability: $r_i(t) = c_i(t) \cdot p_{\text{vel}}(v_i(t)) \in [0, 1]$

### 4.2 Edge-Conditioned Reliability Gating
In `PhaseRelationalGatedAttention`:
```python
r_i = r_joint.unsqueeze(2).unsqueeze(4)  # (B, T, 1, V, 1)
r_j = r_joint.unsqueeze(2).unsqueeze(3)  # (B, T, 1, 1, V)
r_edge = torch.sqrt(torch.clamp(r_i * r_j, min=1e-6))
gated_attn = attn * (0.05 + 0.95 * r_edge)
attn = gated_attn / gated_attn.sum(dim=-1, keepdim=True).clamp_min(1e-5)
```
**Audit Finding:** The geometric mean $q_{uv} = \sqrt{r_u \cdot r_v}$ is currently applied as an external post-hoc multiplier onto the attention matrix. It does not inform the query-key interaction directly.

## 7. Conclusions for Stage 4 Architectural Design

1. **The Base to Beat:** E2 (Topology Only, 57.63% / 0.5656 F1) is the strongest deep model. Stage 4 must directly extend E2.
2. **Fixed vs. Dynamic Hypothesis:** Replacing the static binary adjacency mask with a learned, time-varying dynamic bilateral edge strength $a_{uv,t}$ that is conditioned on joint reliabilities $r_{u,t}, r_{v,t}$ is mathematically and intuitively sound.
3. **Simplicity and Overhead Constraints:** The parameter budget must remain compact (~78K–85K parameters) to preserve real-time CPU capability.
4. **Preservation Rule:** All historical checkpoints, CSVs, and code must remain intact in their respective directories. Stage 4 will live exclusively in `research_stage4/`.
